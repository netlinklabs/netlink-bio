### Fixed
- **`privacy-policy.html`, `terms.html`, `terms-of-use.html`, `username-policy.html`, `investor.html`, and `changelog.html` no longer read the app's `theme` localStorage key.** Each of these public legal/info pages carried a copy of the same inline `<head>` script used by the app (`dashboard.html`/`login.html`/etc.) that checked `localStorage.getItem('theme')` and added `html.dark` when the app had been used in dark mode — since `localStorage` is shared per-origin, a visitor who'd ever toggled dark mode in the app would see these public pages render dark too, even though they're meant to always be light for readability. Removed the inline theme-detection `<script>` from `<head>` in all six files, and removed every corresponding `html.dark ...` CSS rule from each file's `<style>` block (`body`, `.text-primary`/`.text-secondary`/`.text-muted`, `.card`, `h2` border-bottom, `p`/`li` color, `.badge`, `.placeholder`, plus a few page-specific ones: `.warn-box`/`.warn-box p` in `terms-of-use.html`; `.layer-badge-web2`/`.layer-badge-web3`/`.fact-row`/`.fact-label`/`.disclaimer-box`/`.disclaimer-box p` in `investor.html`; `.month-label`/`.tag-new`/`.tag-improved`/`.tag-fixed`/`.tag-security`/`.entry-desc` in `changelog.html`). The non-dark (default/light) version of every rule was left as-is — these pages now render with a single, permanent light appearance (white `#f8fafc` background, white `#ffffff` cards, dark text) regardless of any `theme` value in `localStorage`. The `<html class="light">` attribute and `tailwind.config = { darkMode: 'class' }` were left untouched, since they no longer have any effect once the dark rules are gone. `dashboard.html`, `login.html`, `pay.html`, and the rest of the app's own theme toggle are unaffected — this change only touches the six public pages listed above.
