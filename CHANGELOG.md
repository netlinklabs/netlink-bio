# Changelog

All notable changes to Netlink.bio are documented in this file.

Older entries are archived to keep this file small, see `changelog-archive/` (newest file first,
older entries in older-dated files) if what you're looking for isn't below.

## [Unreleased]


### Security
- **Supabase `profiles`: signed-in users could edit their own `tier`, `tier_expires_at`, verification statuses, `is_black_badge`, `net_id`, `referral_code`, and `net_reward_*` directly from the browser (RLS only checked the row, not the columns), so anyone could self-upgrade to Gold or mark themselves verified.** Migration `lock_profile_sensitive_columns` revokes table-level `UPDATE` from `authenticated`/`anon` and grants it back only on the 40 user-editable columns (bio, contact, wallet, theme, privacy toggles, etc.). No page in this repo writes the locked columns from the client; the `SECURITY DEFINER` trigger `sync_verification_cache`, the Didit webhook, and the service role are unaffected. Verified after the change: `dashboard.html` and `pay.html` still save normally. Any new client-side `profiles.update()` on a locked column will now fail with "permission denied" and must go through an API route instead.

### Fixed
- **tx.html order labels shortened** to "KYC Verification" and "KYB Verification" so they no longer truncate on phones. The receipt Note uses the same label.
- **Identity (KYC) badge is now green for every tier.** Before, Basic and Silver users who passed KYC showed a gray "Previously Verified" badge, and green "Verified Profile" was Gold/Platinum only. Now `identity_verified_at` always shows green "Verified Profile" on bio pages (`api/bio.js`), CV pages (`api/cv.js`), the app header (`shared/nav.js`, bumped to `?v=6` on all pages) and `contacts.html`. Gold "Verified Business" stays Gold/Platinum only; a business-verified Basic/Silver user without KYC still shows the gray badge.
- **Vercel Hobby deploy failed (`exceeded_serverless_functions_per_deployment`, max 12) once `api/orders.js` was added.** Merged two functions without changing any public URL: `api/trails-config.js` is now served by `api/pol-price.js?action=trails-config` (rewrite `/api/trails-config`), and `api/sitemap.js` moved to `api/_lib/sitemap.js`, served by `api/landing.js?action=sitemap` (rewrite `/sitemap.xml`). `api/` is now at exactly 12 functions, so any new endpoint must be added as an `action` of an existing function.

### Added
- **Admin Overview: Top 10 countries by users, and a printable Monthly or Yearly report (A4 PDF).** Users section lists the 10 countries with most users from `profiles.country_code` (names via the browser, "N users have not set a country" for empty ones). A "Print" button at the top right of `admin.html` (finance and super_admin, same look as the CV print button) opens a small dialog: Monthly (last 12 calendar months) or Yearly (last 3 years). It fetches that calendar period, builds an A4 report (header, Finance, Users with plans and countries, Netlink Pay with USD and IDR volume, API requests per endpoint, Storage, footer) into a hidden `#printReport` container and calls `window.print()`, so users pick "Save as PDF" or a printer. `@page` is A4 with 12mm margins, each section is kept together so nothing is cut across pages, and the page title becomes the PDF file name. Backend: `api/_lib/admin.js` `admin-overview` now also accepts `range=month&period=YYYY-MM` and `range=year&period=YYYY` (validated). SQL: `public.admin_overview(p_range, p_period default null)` replaces the one-argument version (calendar periods with an upper bound on every "in range" figure, plus `users.countries` and `users.country_unknown`); migration `admin_overview_periods_and_countries`. Plan, KYC, country, wallet count and storage figures in the report are as of the generation time.
- **Admin Overview tab (finance and super_admin only), with range selector Today, 7D, 30D, 1Y.** Cards and charts for Finance (orders, paid USDC excluding test orders, payments to review, audit entries), Users (KYC vs not KYC, Basic/Silver/Gold from the effective plan, new users, KYC verified per period), Netlink Pay (wallets connected, transactions and types per period) and Storage (database and file storage as a percent of the Supabase Free quota, constants in `api/_lib/admin.js`). Netlink Pay also shows transaction volume in USD (overall, Send, Receive, Swap, Order) with a small IDR conversion under each figure, using the same sources as `pay.html` (`/api/pol-price` and the currency-api rate with its Pages fallback, cached 10 minutes). USDC counts 1:1, POL uses the current price, a swap uses its USDC side, and NET has no market price so it is shown in NET only, not in USD. Overall is Send + Receive + Swap; a transfer between two Netlink users appears in both Send and Receive, and Order paid from Netlink Pay is also inside Send (the page says so). `admin_overview` returns `pay.tx_volume` (successful send/receive/swap grouped by type and token). Every chart has a "View as table" fallback. Backend: new action `admin-overview` in `api/_lib/admin.js` calling the SQL function `public.admin_overview(p_range)` (SECURITY DEFINER, service_role only, Asia/Jakarta day boundaries).
- **API request counting per endpoint.** New `api/_lib/stats.js` (`withStats(name, handler)`) wraps every function in `api/` except `og` (edge) and `cron/`. It increments a daily counter through `public.bump_api_stat()` inside `waitUntil()`, so responses are not delayed and a stats outage never breaks a request. Table `public.api_request_stats` (day, endpoint, action, status class, count; RLS on, service_role grants). `action` is only kept for requests with status below 400 and a normal action name, so random `?action=` values cannot create unlimited rows. Counting starts at release, older requests are not included. Migration: `admin_overview_and_api_stats`. `?v=` on `shared/tailwind.css` bumped 9 to 10 on all app pages.
- **Admin dashboard (`admin.html`, app page, `noindex`) for orders and payments.** Tabs by role: Orders (search by order number, status filter, detail with user, email, Didit session id to copy, verification results, payments), Payments (unmatched, late, matched, ignored; "Sync from chain" pulls new USDC transfers and matches open orders; "Link to order" and "Ignore" need a note), Audit log (super_admin only). "Accept late payment" is on late_payment orders. Backend: `api/_lib/admin.js` (in `_lib`, so no new serverless function) served by `api/orders.js?action=admin-me|admin-orders|admin-order|admin-payments|admin-sync|admin-link-payment|admin-ignore-payment|admin-accept-late|admin-audit`. Roles are checked on the server on every call from `admin_users` (super_admin, finance, support, kyc_reviewer); kyc_reviewer sees only kyc/kyb orders and no payments; every write goes to `admin_audit_log`. `settleOrder` and `claimTransfersForOrder` in `api/orders.js` were refactored so admin actions and the user flow share one settlement path. `admin.html` added to `tailwind.config.js` content, Tailwind rebuilt, `?v=` bumped 8 to 9 on all app pages. MFA (AAL2) is not enforced yet.
- **In-app notifications for KYC payments and results.** New helper `api/_lib/notify.js` writes to `public.notifications` (deduped by `link`, failures never break a payment or webhook). `api/orders.js` notifies "Payment received" when an order turns paid and "Partial payment received" on underpayment; `api/webhooks/didit.js` notifies "Identity verified", "Verification rejected", or "Please resubmit your documents". Notifications show in the existing tab on `tx.html`. Requires migration `orders_paid_tx_hash_notify_grants` (adds `orders.paid_tx_hash`, grants `service_role` SELECT and INSERT on `notifications`).
- **tx.html labels order payments.** A send that matches `orders.paid_tx_hash` shows "Identity Verification (KYC)" with the order number instead of "Sent USDC", and its receipt carries the order in the Note row.
- **identity.html KYC status.** Identity badge now shows Not Started, Awaiting Payment, Paid, Pending Review, Needs Resubmission, Rejected, or Verified, combining the Didit result (`profiles.identity_verification_status`) with the user's latest KYC order (read via RLS). An action row links to `/checkout` to continue payment, start verification, or try again. Labels: `pending` is now "Pending Review", `declined` is now "Rejected". Migration `create_kyc_sessions` applied (RLS on, users read own, admins `super_admin`/`kyc_reviewer` read, writes via API only).
- **Didit verification session for paid KYC orders.** `api/orders.js?action=didit-session` (POST `order_id`) creates or resumes the Didit session only for a `paid` kyc order, with `vendor_data` = profile id and callback to `/identity`. Limits: 3 new sessions per rolling 24 h and 10 per order (Didit bills per session). Sessions are stored in `kyc_sessions` (migration pending approval, the action fails until it exists). Needs env `DIDIT_API_KEY` and `DIDIT_WORKFLOW_ID`. `checkout.html` paid panel now has a "Start verification" button.
- **Paid-order backend for KYC (KYB and plans reuse it later): new `api/orders.js` and Supabase tables `orders`, `order_payments`, `admin_users`, `admin_audit_log`.** The checkout UI below is the first user-visible part.
  - **`api/orders.js`** is one function dispatched by `?action=create|status|check-payment|cancel` (`status` accepts `order_id`, or `type` to resume the caller's latest open or paid order) (this is the 12th and last Vercel Hobby function slot, so future order features must be added as actions here). Every action needs a Supabase session. The price comes from the server (`PRICES.kyc` = 2.5 USDC), never from the request. Native USDC only (`0x3c49...3359`), not USDC.e.
  - **Payment matching needs no tx hash from the user.** `check-payment` pulls incoming USDC transfers to the finance wallet from Alchemy, stores each in `order_payments` (unique per `tx_hash` + `log_index`), and assigns a transfer to an order when it comes from the order's sender address, or when its hash equals the optional `claimed_tx_hash` (hash wins, for exchange withdrawals). Statuses: `paid` (within 0.05 USDC tolerance, overpay counts as paid), `underpaid` (remaining amount is shown, later transfers add up), `late_payment` (arrived after the 3-day expiry, an admin decides), `expired`. Unmatched transfers stay `unmatched` for admin review. Amounts are integer micro-USDC (BigInt).
  - **Requires two Vercel env vars**: `FINANCE_WALLET_ADDRESS` (public receiving address only, never a key) and the existing `SUPABASE_SERVICE_ROLE_KEY` / `ALCHEMY_API_KEY`. Without `FINANCE_WALLET_ADDRESS` the API returns a generic 500 by design.
  - **Supabase**: `orders` (one active order per user per type and per sender address, `pay_to_address` snapshotted per order so moving to a Safe later does not affect old orders), `order_payments`, `admin_users` (one row per person per role: `super_admin`, `finance`, `kyc_reviewer`, `support`), `admin_audit_log` (append-only, enforced by a trigger). Clients only have `SELECT` under RLS; all writes go through the API with the service role. `has_admin_role(text[])` drives the admin RLS policies. Initial admins seeded: owner as `super_admin`, one team member as `finance` and `kyc_reviewer`.

- **New `checkout.html` (app page, `/checkout?type=kyc` or `/checkout?order=<id>`) and the "Order KYC Verification" button on `plans.html` now opens it.** The user picks Netlink Pay wallet or External wallet (sender address, personal wallet recommended, not an exchange). Then the order page shows the total, remaining amount, expiry, and status. External orders show the receiving address (copy + QR), the exact amount, "Polygon, native USDC" warnings, an optional transaction hash field for exchange withdrawals, and an "I have paid, check now" button; every open order is also re-checked on open and every 20 seconds while the tab is visible. Handles `paid`, `underpaid` (shows what is still due), `expired`, `late_payment`, `cancelled`, unknown orders, already-verified users, and a missing Netlink Pay wallet. All UI copy is English with no em dashes.
- **`pay.html`: new order payment mode (`/pay?order=<id>`), used by checkout for Netlink Pay orders.** After the profile loads, the page fetches the order and, only if it is a `netlink_pay` order in `awaiting_payment`/`underpaid` whose sender wallet is the currently connected wallet, opens the Send modal titled "Pay order <no>" with USDC, the finance address, and the remaining amount locked (read-only fields, token picker disabled, contact/QR buttons hidden). `doExecuteSend()` reads token/recipient/amount from the order, not from the form fields, so editing the DOM cannot change what is sent. The normal wallet-session check (`sessionMatchesCurrentWallet()`) and re-auth steps are unchanged and still run. After a successful send it returns to checkout, which confirms the payment. Closing the modal or any failed validation returns to the regular Send behavior, and the regular Send flow is untouched.
- **Tailwind**: `checkout.html` added to `tailwind.config.js` `content`, `shared/tailwind.css` rebuilt (only 4 classes added, none removed), and `?v=` bumped from 7 to 8 on every app page.
